What happens inside a language model when I send a prompt?

A common decoder language model turns token context into a distribution for the next token, repeatedly.+

YOUR PM JOB · Explain model behavior without needing to train one.

  1. Text → token IDs
  2. Embeddings + position
  3. Attention + feed-forward layers
  4. Next-token scores
  5. Select token → repeat

Pretraining adjusts weights using many examples. Inference uses the learned weights to process the current context; an ordinary chat does not itself retrain the weights. Attention lets positions combine information from available context. Architectures differ, and reasoning/tool-use systems add surrounding steps. Fluent generation can still be unsupported by evidence.

Worked example · illustrative

In “Please summarize this policy,” the policy and instructions are input context. The model generates a summary one token at a time. A longer context window permits more input, but does not guarantee the model uses every detail correctly.

Try it

Draw the path from a policy document to a summary. Mark where source retrieval, model inference, and human review happen.

What a good explanation should cover
  • Distinguish training from inference.
  • Explain tokens and context without calling them exact words.
  • Explain why plausibility is not factual verification.

02AI suggested · AI answered

Why do tokens, context and output length affect product cost?

Count every call, its input and billed output, then measure the cost per successful outcome.+

YOUR PM JOB · Estimate workload and identify the expensive stage.

  1. User + instructions + history
  2. Retrieved text + tool results
  3. Input tokens
  4. Output / reasoning tokens
  5. Usage record → bill

Token boundaries depend on the model’s tokenizer. Repeated history and tool outputs can be billed as later input. A context limit is capacity, not a budget or correctness guarantee. Subscription allowances, API billing and hosting costs are separate concepts. Reasoning accounting and cache pricing vary by provider.

Worked example · illustrative

Hypothetical rates of $2 input and $10 output per million make a 2,000-in / 500-out call cost $0.009. Three equal calls cost $0.027 per task before tools or infrastructure. If the task fails, the spend still happened.

Try it

Use the cost lab for one assistant task. Include retries and the success rate, then explain which assumption drives uncertainty.

What a good explanation should cover
  • Show units and all model calls.
  • Separate model cost from total cost.
  • Use logs rather than a word-count rule for real bills.

03AI suggested · AI answered

Should I improve the prompt, add retrieval, or fine-tune?

Diagnose the gap before changing the model. Product improvement and weight training are different levers.+

YOUR PM JOB · Choose an intervention from observed failure modes.

  1. Collect failures
  2. Label knowledge / behavior / workflow gap
  3. Try smallest intervention
  4. Compare held-out evals
  5. Monitor regressions

Prompting changes the instructions and examples supplied at inference. Retrieval supplies relevant external information; it does not update model weights. Fine-tuning adjusts weights with training data to shape behavior on a task. None guarantees correctness. Training needs supported tooling, rights to data, good examples, and a comparison against a simpler baseline.

Worked example · illustrative

A support assistant missing yesterday’s policy needs fresh evidence, not memorization of a new fact through training. A stable extraction task with many consistent labeled examples may justify a fine-tuning experiment after prompt baselines.

Try it

Take five failed responses and classify their causes. Write the cheapest experiment that could disprove your diagnosis.

What a good explanation should cover
  • Separate missing knowledge, inconsistent behavior and broken tooling.
  • Keep a held-out test set.
  • Measure new regressions as well as average improvement.

04AI suggested · AI answered

How do I know whether retrieval is helping or hurting?

Evaluate evidence retrieval separately from whether the final answer uses that evidence correctly.+

YOUR PM JOB · Debug a knowledge assistant stage by stage.

  1. Permission-filtered documents
  2. Chunks + index
  3. Retrieve candidates
  4. Rank + fit context
  5. Answer + supporting passage

Semantic search can find related passages without matching exact keywords. Relevance alone does not prove freshness, authority, completeness or user permission. Chunking and ranking shape what reaches generation. A citation can exist without supporting the claim; inspect the passage, not just the link.

Worked example · illustrative

If a refund answer is wrong, check whether the current refund policy was indexed, retrieved, ranked high enough, and actually supported the answer. These are different failure locations.

Try it

Create three questions with known supporting passages. Include one with no answer in the corpus, and require an explicit “not found.”

What a good explanation should cover
  • Test retrieval and grounded answering separately.
  • Include stale and unanswerable cases.
  • Apply permissions before exposing passages.

05AI suggested · AI answered

How do I decide that an AI feature is good enough to ship?

Define success for a user job, test representative segments, and set a release rule before reading the scores.+

YOUR PM JOB · Turn quality into a defensible release decision.

  1. User job + risk
  2. Cases + rubric
  3. Human calibration
  4. Run candidate + baseline
  5. Segment results → release / revise

Offline evals help compare versions; live outcomes test whether people benefit. Keep training examples separate from held-out evaluation. Use deterministic checks where possible and calibrate model judges against humans. A benchmark can help shortlist models but cannot replace your task set. Watch false positives, abstentions and costly rare failures.

Worked example · illustrative

A support draft can be fluent while quoting the wrong policy. Score source support, accuracy, completeness and unsafe actions separately. A small perfect test set is weak evidence if it contains only easy cases.

Try it

Draft a ten-case eval with routine, ambiguous, unanswerable and adversarial inputs. Write a rollback condition and name the accountable owner.

What a good explanation should cover
  • Use observable criteria and representative cases.
  • Calibrate grading with human examples.
  • Separate offline scores from user outcomes.

06AI suggested · AI answered

What belongs in an agent harness rather than the model?

The model proposes actions; the surrounding system manages context, tools, permissions and the work loop.+

YOUR PM JOB · Design a bounded workflow that can recover from failure.

  1. Task + state
  2. Model proposes action
  3. Check permission + execute tool
  4. Observe result
  5. Stop / retry / escalate

A fixed workflow follows predefined steps; a more autonomous agent chooses more of the sequence. More autonomy adds failure paths. Tool schemas, state, stopping conditions, retries and traces affect reliability. Give consequential writes a clear authorization path. A retry must not accidentally duplicate a payment or message.

Worked example · illustrative

A purchasing assistant can search vendors freely while a purchase requires a specific authorized budget and destination. An ambiguous tool timeout should trigger reconciliation before another charge attempt.

Try it

Sketch an agent that prepares a purchase order. Mark read actions, write actions, retry limits and human checkpoints.

What a good explanation should cover
  • Distinguish model and orchestration responsibilities.
  • Define stop and escalation conditions.
  • Handle retries without duplicating side effects.

07AI suggested · AI answered

How do I reduce cost and latency without quietly lowering quality?

Compare cost per successful task and end-to-end latency, not just the cheapest token rate.+

YOUR PM JOB · Optimize a measured bottleneck under a quality floor.

  1. Trace baseline
  2. Locate bottleneck
  3. Change one lever
  4. Re-run quality eval
  5. Compare cost / success + p95 latency

Shorter outputs and fewer sequential calls can reduce waiting. Caching needs eligible reusable content and real hits; include write/storage fees when applicable. Routing and smaller models can save spend but need escalation quality checks. Batch work when delay is acceptable. Distillation and quantization are advanced options with quality and operational trade-offs, not automatic wins.

Worked example · illustrative

A cheaper model at 50% success can cost more per successful task than a stronger one at 95%. A streamed response may feel faster even when total completion time is unchanged.

Try it

Choose one lever for a research assistant: less context, shorter output, routing or fewer calls. Define a quality floor and a latency measurement.

What a good explanation should cover
  • Use full workload cost and a stable quality threshold.
  • Distinguish perceived, first-token and total latency.
  • Include cache misses and retries.

08AI suggested · AI answered

Where does value accumulate in the AI industry?

Map compute, model access, data/tool infrastructure and applications; then ask who owns a valuable workflow.+

YOUR PM JOB · Explain the market through customer jobs and constraints.

  1. Compute + cloud
  2. Model capability
  3. Data + tools + observability
  4. Application workflow
  5. Customer outcome + feedback

One company can span several layers. API access, open weights, distribution, proprietary data and integration depth create different trade-offs. Open weights do not imply zero operating cost or unrestricted licensing. Public market capitalization and private funding valuation are different measures; neither alone predicts product quality.

Worked example · illustrative

For a support copilot, the buyer may be the support leader, daily users are agents, and administrators control data access. The relevant moat hypothesis might be workflow integration and feedback quality rather than access to one model.

Try it

Compare two products on buyer, user job, distribution, switching cost and outcome evidence. Use dated primary sources, and label strategic interpretation.

What a good explanation should cover
  • Separate facts from moat hypotheses.
  • Distinguish buyer, user and administrator.
  • Avoid rankings from incomparable valuations.
