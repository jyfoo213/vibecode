How could AI Atlas support mobile, desktop and an optional shared database?

The current responsive website already works in mobile and desktop browsers. Installed apps and cross-device data sync are separate choices; a shared database would sit behind authentication and an authorised API.

Read the full answer

For browser compatibility, keep one responsive HTML/CSS/JavaScript frontend. If installation or deeper device integration becomes valuable, consider a PWA, a desktop wrapper, or a native/cross-platform mobile client; none automatically creates shared storage. For cross-device data, clients could use a shared authenticated API and per-user database records while public content remains on a CDN. Backend logic could use JavaScript/TypeScript or another suitable language; the database could be managed PostgreSQL. These are architectural options for learning only. No installed app, service worker, sign-in, API backend or shared database has been built or provisioned.

How is AI Atlas built: frontend, backend, hosting and languages?

HTML and CSS present the site; JavaScript runs the interactions. GitHub Pages serves static files. Node.js powers development/build checks, not a live backend. Personal state stays in browser storage.

Read the full answer

AI Atlas is a static frontend built with HTML, CSS and browser JavaScript modules, with public content in JSON. GitHub Actions runs Node.js tests and build scripts, then publishes the dist/ files to GitHub Pages. The browser fetches those files and saves personal notes, verdicts and Done/archive state in localStorage. There is no production application server, shared database, sign-in or runtime model API. The cloud coding workspace and Node preview server are development tools, separate from the published site. A future authenticated backend/database could add cross-device sync, but it has not been provisioned.
