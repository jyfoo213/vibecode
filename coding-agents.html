THE AI PM FIELD GUIDE

CODING AGENTS / 5 MIN READ

Claude Code & Codex.
Inside the work loop.

Both connect a model to tools, project context, and a feedback loop. The useful comparison is the whole working system.

Prompt → context → choose an action → use a tool → inspect the result → repeat or finish. This is a simplified public architecture, not access to either model’s hidden reasoning.

01 / MODEL

Chooses the next move

Produces text or requests a tool action from the context it receives.

→
02 / HARNESS

Runs the work loop

Assembles context, routes tools, and applies the configured execution boundaries.

→
03 / WORKSPACE

Holds the project

Files, dependencies, commands and test results provide the working evidence.

01 / FROM PROMPT TO IMPLEMENTATION

Six useful steps to watch.

Steps can repeat, overlap, or be skipped. A code explanation may need no edits; a bug fix may revisit the same test several times. The Atlas examples below are illustrative, not transcripts of a private model process.

1. Frame the task and constraints

The request joins the session’s instructions and available project context. A useful target includes observable completion criteria.

Atlas example: “Reorganize navigation, preserve URLs, support mobile, and test it.”

2. Inspect the relevant context

Search and read the repository, instructions, current changes, and errors. A repository on disk is not the same as every file being inside the model’s context.

Atlas example: inspect AGENTS.md, existing headers, page routes, and the build script.

3. Choose a next action

The model can answer, ask for missing information, or request a tool. A displayed plan helps communicate intent; it is not a guarantee of the eventual result.

Atlas example: group pages by reader task and choose a shared navigation configuration.

4. Execute through the harness

The harness handles the tool request under the session’s permissions. Tools can read or change files and run commands. Available tools and access depend on the surface and configuration.

Atlas example: edit shared navigation, generate headers, and run the preview.

5. Observe, test, and revise

Tool results become evidence for another decision. An error can lead to a different edit or command. Tests only support the cases they actually exercise.

Atlas example: a fast menu-switching check exposed a timing bug; change the handler and rerun browser checks.

6. Hand back a reviewable result

Inspect the diff, summarize changes and checks, and identify unresolved gaps. Commit, PR, merge, and deployment are workflow actions requiring the relevant access and authorization; they are not automatic consequences of generating code.

Atlas example: publish a focused PR, check the Pages workflow, and verify the live URL.

Architecture references: Claude Code’s work loop and OpenAI’s Codex agent-loop explanation.

03 / YOUR SHARED INSTRUCTIONS

One policy, compatible entry points.

Atlas keeps its project policy in AGENTS.md. Codex documents automatic discovery. Claude Code’s current documentation describes direct AGENTS.md loading when no overriding CLAUDE.md is present, with version and session caveats. Older or differently configured clients may need an explicit reference or import. Ask each agent to summarize the instructions it loaded; don’t assume identical discovery.

What does a harness add beyond a chatbot?

A harness turns model requests into operations, carries results back, and manages the working context and execution rules. The model does not need to emit the entire finished project in one reply. A fluent final message still does not prove the files, tests, or deployment are correct.

04 / TURN THE COMPARISON INTO AN EVAL

Same task. Same quality bar.

Use the same starting commit, instructions, tool access and completion criteria. Record the model, reasoning setting, surface and environment warmth.

  1. Task: fix a mobile menu without breaking desktop links.
  2. Evidence: inspect the diff, test keyboard interaction, and verify every route.
  3. Efficiency: compare wall-clock time, interventions and available usage/cost records. Separate workspace startup from model waiting.
  4. Verdict: score the result against your rubric. One task is a case study, not a universal winner.
